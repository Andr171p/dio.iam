## Где должны храниться данные

| Данные | Источник истины |
|---|---|
| name, slug, logo_id, status | Organizations |
| Membership, роли организации | Organizations / Access |
| ИНН, КПП, ОГРН, юридический адрес | Business Registry |
| Проверка реквизитов, статус подтверждения | Business Registry |
| Клиенты, сделки, история взаимодействий | CRM |
| Договоры, счета, платёжные реквизиты по соглашению | Contracts & Billing |
| Заявки, исполнители, наблюдатели | DIO Desk |
| Доступ к статьям и коллекциям | Knowledge Base |

**Organization** - логическое пространство для работы пользователей.

**LegalEntity** - реально существующий субъект права, который может заключать договоры и проходить проверку реквизитов.

Это решает несколько проблем:
- Один tenant может объединять несколько ООО.
- Компания может иметь отдельные tenant для разных направлений или окружений.
- Организация может существовать без заполненных юридических реквизитов.
- Юридическое лицо может быть контрагентом, не имея собственного tenant в DIOS.
- Один контрагент не должен автоматически получать доступ к внутренним данным другого tenant.


| Тип | Что подтверждает | Где реализовать |
|---|---|---|
| Email / Domain Verification | Контроль над email или доменом | IAM / Organizations |
| Legal Entity Verification | Существование юридического лица, соответствие реквизитов | Business Registry |
| Organization Ownership Verification | Полномочия пользователя представлять это юридическое лицо | Business Registry + IAM |

**Виды Scopes**:
- own — собственные ресурсы.
- organization — ресурсы текущей организации.
- all — все ресурсы в пределах разрешённой области, которая должна быть определена явно.
